# Read-API load test (k6)

`ops/k6/read-api.js`, k6 0.54.0 in Docker against the service on the host (default config, 16,300+ insights in Postgres,
analytics stores populated). Constant arrival rate for 60 s; request mix: 50% filtered search
(`/api/insights?intent=…&size=20`), 30% Kafka Streams interactive query (`/api/brands/{brand}/sentiment`),
20% aggregate stats (`/api/insights/stats`). Machine: i7-12700H, 16 GB, Windows 11, Docker Desktop.

| Target rate | Requests | Failed | p50 | p95 | p99 | max |
|---:|---:|---:|---:|---:|---:|---:|
| 200 req/s | 12,000 | 0 | 4.83 ms | 17.43 ms | 24.86 ms | 422.59 ms |
| 500 req/s | 30,000 | 0 | 4.87 ms | 19.44 ms | 24.50 ms | 46.49 ms |

The 422 ms max at 200 req/s is the first requests after startup (JIT warm-up); the later 500 req/s run has none.
Both rates were sustained exactly (200.0 and 500.0 req/s). Higher rates were not tried.

Command: `docker run --rm -v "$PWD/ops/k6:/k6" -e BASE=http://host.docker.internal:8080 -e RATE=500 grafana/k6:0.54.0 run /k6/read-api.js`
